# 原型标注稿

把实际产品界面和真实实现进度放在一起，让接手的人能指着某一处看懂：这里已有些什么，还差什么，现在能做哪一步，需要谁补条件。交付的是供讨论和对接的 HTML 标注稿；其中的示例画面不代表系统已经上线。

本技能适合放在项目的 `.agents/skills/annotate-prototype/` 下，整目录复制即可复用。按当前项目发现资料、输出目录和可用工具，不依赖固定产品、技术栈、浏览器、操作系统或其他技能。

## 确定范围与现有材料

从用户请求和项目约定确定目标原型、版本及页面边界。先查已有需求清单、原型链接、设计文件、源码、工作计划和验证记录；可以自行找到的事实不再向用户索要。

- 沿原型入口查看所有属于目标范围的子页面、页签、弹窗及关键展开状态，包括空态和错误态（若原型有）。页面数与展开状态数分开记录。
- 背景重复面板不重复计需求。共用交互、无独立画面的规则和外部承接项仍保留入口，不为它们虚构产品按钮。
- 复用已有需求编号；只有没有清单时才建立稳定编号。不要把原型的一个大报表笼统计成一项，也不要把同一能力在不同页面的复用重复算进总量。
- 如果用户已提供完整清单和最新证据，只补核影响标注的事实，不默认重做整套项目规划。

确实缺少决定范围的资料时，说明缺哪一份，同时推进已有材料能支持的部分。无法打开某个原型状态就标为未核实；不能靠源码或想象补出该状态，并称为实际原型。

## 核实原型画面

能实际渲染时，打开原型并检查视觉内容，优先用原始画面承载进度标注。确认截到的是产品画面，而不是声明、登录、加载或错误页；截图之外的设计注释也要读。

可使用在线原型、项目内设计文件或用户提供的画面。按条件选择：

| 条件 | 合适的呈现方式 |
| --- | --- |
| 已有可访问且布局明确的原型，主要目的是标进度 | 原型截图加可点击标注，保留来源和日期 |
| 用户要求能操作控件，或截图不足以解释交互 | 依据原型重建相关 HTML，注明重建范围，示例行为与实际实现状态分开 |
| 部分画面缺失、无法渲染或只有文字资料 | 先交付有依据的部分；缺失页保留文字占位及所需资料，不称完整复刻 |

不要为了标进度重新设计整套界面。模型、地图、视频和业务数字可保留原型示例，但必须让人看出是示例；没有实际来源的内容不得包装成实时结果。

## 将每一处标注与实现证据对应

读取[需求、标注与证据](references/evidence.md)，组织一份供画面标签、详情和完整清单共同使用的数据。

对照需求查看对应实现入口、消费者及最新验证记录。区分通用代码存在、当前需求编码完成、本地验证、真实联调和页面验收；找不到前端或其他组件源码时写待核实，不断言它没开发。

每个标注用业务语言回答：

1. **已有些什么**：明确完成到哪个范围、哪一层。
2. **还缺什么／卡在哪里**：区分待开发、内部前置、产品决策、外部数据或环境、缺少证据。
3. **需要谁配合**：能够确认的角色与需要提供的内容；负责人不清楚就写待落实。
4. **下一步做什么**：可执行的动作及边界，而不是重复“待对接”。

不能把技术侧可以自行核查的事实全部转交 PM，也不能替 PM 批准业务取舍。建议和已确认规则分开；旧系统同名字段、任务级字段、占位值和假数据都不等于需求所需的真实数据。

默认沿用以下颜色；用户指定其他配色时服从用户：

- **绿色**：标注标题限定的范围已经完成，右下角显示勾。例如“查询接口已本地实现”，不能简写成“列表页完成”。整页确有验收证据时才可以标整页完成。
- **蓝色**：所列范围可以立即继续。若只能核查接口或做隔离测试，标题就注明这一步，不能把整个真实接入标蓝。
- **橙色**：所列交付范围有卡点或待核实，说明具体缺口和补齐者。外部负责／本侧冻结不算完成。

一个界面部分已做、部分未做时，拆成范围清楚的标注，或在绿色局部能力旁明确列出剩余缺口；不要给整片未完成界面涂绿。同一需求可以关联多处标注，但需求总量仍只计一次。不把工作块、标签、测试用例数量换算成完成率。

## 制作 HTML

制作前读取[HTML 呈现与检查](references/html.md)。根据资料和页面复杂度选择结构，不要求套用固定模板。

通常提供页面／状态切换、画面上的进度标签、可展开详情和原型来源；画面缩小后文字难读时提供局部放大。需要核对完整性时提供按原编号查看的清单。搜索、筛选等只在条目较多且确有帮助时增加。

保持画面标签简短，完整解释放在旁边或展开层。非技术读者应能直接读懂缺口与下一步，路由、字段名和验证细节放在证据区。

用户要求独立 HTML 或准备转发时，优先生成无需运行服务、无需安装依赖的单文件，将必要图片和数据内嵌。资源太大或项目已有明确格式时可用随附资源，但要明确一起携带哪些文件。若只要求会话展示，按当前环境能力呈现，不强制新建项目网站。

## 检查、落地与更新

按参考文档实际检查覆盖、状态边界、标签位置、窄屏、展开关闭、局部放大和清单定位（若有）；仅声明真正执行过的检查。浏览器验证是在验 HTML，不是验产品业务。

保存到项目已有的文档或交付目录，并在已有进度入口加入链接。保留原编号和带日期的历史记录；更新稿注明变化依据，不用新图覆盖无关计划。标注内包含快照日期、原型来源和验证边界，不能让静态文件看起来会自动跟随代码更新。

这项任务不自动授权产品开发、工作区重组、发布、业务数据变更或现场联调。不为给标注稿盖章而重跑全项目构建或连接真实设备；确实需要的新验证按当前请求与项目规则处理。

最终给文件入口、阅读方式和最重要的边界。留下可直接使用的交付物；缺少某些材料时保留已完成部分，并准确说明未覆盖范围。
