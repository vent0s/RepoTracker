# RepoTracker 技术设计

RepoTracker 是 Windows 上的 Git 状态观察工具：从任务栏应用按钮展开面板，查看用户主动添加的仓库，并按手动分组组织列表。本文记录 2026-10-16 用户确认原型后采用的开发基线，不表示功能已实现。开发进度只在[桌面开发里程碑](../devSchedule/桌面应用开发/doc/里程碑-桌面应用开发.md)维护。

## 技术路线与职责

采用 C# / WPF / .NET 10 / Git CLI，使用 MVVM 分离视图与应用状态，JSON 保存配置。当前不引入 Web 服务、数据库、Rust 或 libgit2。M1 已锁定 SDK 10.0.201 和测试依赖，生产代码目前只用框架自带库；恢复、构建与版本入口见[开发与运行](开发与运行.md)。M6-03 的 Windows x64 便携预览包固定包含 .NET / WPF 10.0.13；系统支持条件仍以发行矩阵的实际验证为准。

| 层 | 职责 | 依赖方向 |
|---|---|---|
| Desktop | 任务栏窗口、焦点、布局、输入校验反馈、设置、文件夹选择与目录打开 | 调用 Core，通过组合入口注入 Infrastructure |
| Core | 仓库与分组规则、来源匹配、状态模型、调度策略、端口接口 | 不依赖 WPF 或具体 Git 进程实现 |
| Infrastructure | Git 子进程、配置原子保存、路径解析、事件监听、系统适配 | 实现 Core 接口 |

状态采集在后台执行，通过不可变快照更新 UI；不在 UI 线程等待进程，不为每个仓库常驻一个 Git 进程。

## 任务栏窗口

主窗口使用 `ShowInTaskbar=true`，收起使用最小化，保持任务栏按钮可见与后台调度运行。接受标准 Alt+Tab 行为。通过单实例激活及一致的 AppUserModelID 避免重复窗口与图标。

任务栏点击负责激活或恢复窗口，前台重复点击遵循系统最小化行为。默认失焦收起，但本应用设置、菜单及文件选择器不触发误收起；“保持展开”关闭自动收起。应用内退出真正结束进程并回收子进程；固定到任务栏由用户主动操作，不能静默固定。

窗口定位首先保证当前显示器工作区内可见，按任务栏边缘或上次位置展开。精确锚到应用图标尚未验证；不能使用通知区的 `Shell_NotifyIconGetRect` 代替任务栏应用按钮定位，也不以 Explorer 注入或旧 DeskBand 为依赖。验收覆盖多屏、DPI、任务栏自动隐藏、图标重排和键盘激活。

## 数据与配置

| 模型 | 关键字段与约束 |
|---|---|
| Repo | 稳定 id、worktreeRoot、gitDir、commonDir、别名、可空 groupId、添加时间；remote URL 仅临时读取，不写入 profile |
| RepoGroup | 稳定 id、name、order、collapsed；名称不作外键 |
| SourceRule | id、显示名称、主机规则、图标类型；初始 GitHub / GitLab 规则与用户规则一样可编辑、删除 |
| RepoStatus | 分支或 detached SHA、dirty、可空 upstream/ahead/behind、本地检查时间、成功远程检查时间、数据新鲜度、分层错误 |
| Settings | 本地和远程间隔、并发上限、远程开关、登录启动、保持展开、主题及应用缩放 |

仓库身份以规范化的工作树根目录为准；不能按 commonDir 合并不同 worktree。重复路径和路径别名需统一判定，目录不可达时保留记录，不能误删。

配置存入 LocalAppData 下 RepoTracker 专属目录，带 schemaVersion、原子替换与损坏备份。测试必须注入独立配置根，不能覆盖用户真实配置。旧配置缺少 groupId 或引用失效时回退未分组；遇到未知的更高 schema 版本不覆盖原文件，给出可恢复提示。

具体文件为 `state.json`，M5 将 schemaVersion 升为 4。顶层包含 `repositories`、`groups`、`ungroupedCollapsed`、`sources`、`remoteEnabled` 与 `preferences`；仓库字段为 `id / worktreeRoot / gitDir / commonDir / displayName / groupId / addedAt`，分组为 `id / name / order / collapsed`，来源为 `id / name / pattern / icon`。schema 1（或未写 schemaVersion）允许缺少 groups 与 groupId；schema 1 / 2 升级时远程强制关闭、填入默认来源规则。schema 3 中空规则列表表示用户删除全部规则，重启不自动补回。schema 3 升级保留既有 remoteEnabled 与 sources，补入默认 preferences。preferences 包含 localIntervalSeconds（默认 15，5–300）、remoteIntervalMinutes（默认 10，1–120）、localConcurrency（默认 2，1–4）、keepExpanded（默认 false）、theme（Dark / Light，默认 Dark）和 scalePercent（100 / 125 / 150，默认 100）。范围校验在保存前完成，发布后立即更新调度；并发降低不取消活动检查。登录启动以系统 Run 登记为准，JSON 不保存第二份开关。

配置事务以同目录独占锁文件、读入字节的 SHA-256 版本和原子替换实现。写入先落到同目录唯一临时文件并 flush，再 replace / move；上一个有效快照保存在 `.bak`。保存成功才发布内存快照，外部修改或文件占用时保留原状态。损坏配置先复制原字节到独立恢复文件，再读有效备份；未来版本或不可读配置只读打开。配置上限为 4 MiB。

仓库发现使用 `rev-parse --path-format=absolute --show-toplevel --absolute-git-dir --git-common-dir`，通过目录句柄取得最终路径以消除 junction 别名；仅按工作树根去重。进程以参数数组启动，清除继承的 `GIT_*` 覆盖，禁用交互凭据，默认 10 秒超时；取消与超时回收进程树。撤销最近一次移除保留稳定 ID，当前会话有效。

## 手动分组

采用单层、单归属。groupId 为空表示系统“未分组”，它不可重命名或删除，始终排在最后。自定义组按创建顺序显示；空组合法，不包含嵌套、自动归类或拖动排序。

组名去除首尾空白后为 1–30 个字符，按 Unicode NFC 规范化后以不区分大小写的规则判重；长度口径在实现中统一为用户可见文本元素。改名不改归属。移动只修改 groupId；删除分组先确认受影响数量，再将成员 groupId 清空并删除组，作为一次配置更新保存。折叠状态持久化，但不暂停采集。

添加仓库可选择分组，默认未分组。保存时目标组失效则回退未分组并提示。分组操作不移动文件、不修改远端 URL、分支或 upstream。

## Git 状态与采集

本地状态入口采用参数数组调用 `git --no-optional-locks -C <path> status --porcelain=v2 --branch -z --untracked-files=normal`，并通过适配器完成仓库发现、worktree 路径及来源读取。不得拼接 shell 命令。缺少 Git、访问失败、超时、取消分别映射为可理解的状态，不弹凭据窗口。

解析保留 NUL 分隔，覆盖初始未提交分支、未跟踪、暂存、冲突、重命名、无上游及分离 HEAD。`branch.ab` 缺失表示未知或不可比较，不能补 0。工作区干净不等于与远程同步。领先和落后只相对本地已知上游，必须显示数据时间或“尚未远程检查”。

本地初始间隔 15 秒，全局并发上限 2；监听事件只补充轮询，兼顾工作区变化与 worktree 的 gitdir/commondir。合并重复事件，禁止同仓库检查重入，暂停或恢复后避免瞬时启动全部任务。超时、退出与取消需回收子进程；移除仓库后旧结果不得重新插回列表。

M3 使用单个可唤醒队列，空队列等待信号，不持续轮询 UI。周期从上次检查结束计算；事件去抖 400ms、去抖上限 2 秒，任务启动间隔至少 100ms（排队和 Git 执行时间另计）。移除时取消该任务，同一 ID 或工作树重新加入后仍等旧任务释放并发槽；发布时核对当前条目实例，阻止旧结果覆盖新条目。暂停与恢复由 Windows 电源消息接入，并支持可控 TimeProvider 验证。

状态读取额外固定 `--git-dir` / `--work-tree`，避免记录中的 Git 目录失效后误向上查找父仓库。`--no-optional-locks` 避免状态刷新回写索引，`core.fsmonitor=false` 禁止采集时执行用户的 fsmonitor hook，`GIT_NO_LAZY_FETCH=1` 禁止部分克隆在缺对象时触发隐式下载。退出码和异常映射为缺 Git、不可达、非仓库、权限、超时、格式或一般失败，不把原始 stderr 中的路径和凭据直接展示。

本地与远程快照分别记录尝试时间、成功时间和检查中状态，仅在本次运行中保留，不写入 JSON。本地快照另含监听可用性与已脱敏的 remote 主机。失败保留旧数据并标注失败、上次成功时间；后续成功覆盖错误。UI 更新既有仓库行的状态属性，避免检查期间重建分组、关闭菜单或重置滚动位置。重启后重新检查，不把旧会话成功时间当作本次已检查。

远程层只允许 fetch 类操作，不执行 commit、push、pull、stash 或 tracking 配置写入。fetch 会下载对象并更新 Git 元数据，不能称为严格只读。开发默认值设为首次启动关闭，用户主动开启时说明作用范围；原型中的开启画面仅为演示状态。启用后初始间隔 10 分钟并错峰，同 commonDir 的写入型采集串行。

M4 采用独立远程队列，全局并发 1，因此共用 commonDir 的 worktree 也不会重叠 fetch。默认每次完成后 10 分钟再次排队，相邻任务至少间隔 1 秒。开关保存成功才改变调度；关闭、暂停、移除和退出取消相关任务，快速关闭再开启也丢弃旧任务结果。成功后请求本地队列重新读取上游计数；关闭和失败均不停止本地检查。

每次执行前重新读取 remote 配置，选择 origin，否则按名称的 ordinal 顺序选择第一个；只接受单 URL 的 HTTPS / SSH / scp。拒绝带密码、HTTPS userinfo、查询参数的 URL，以及本地路径、URL 重写、mirror、自定义 upload-pack。仅支持一个标准 `refs/heads/*:refs/remotes/<remote>/*` 或同名的单分支映射，可有 `+` 前缀；其他映射跳过并说明，不替用户改配置。fetch 使用显式 URL、已校验 refspec、空 `--refmap=` 和排除 `refs/heads/HEAD` 的负 refspec；拒绝可将写入重定向到其他命名空间的符号引用。

fetch 禁止自动 tags、prune、子模块递归、FETCH_HEAD 写入、自动维护与 commit-graph，使用 atomic 更新并禁用 hooks。允许的协议只有 HTTPS / SSH，关闭 HTTP 重定向。Git 执行上限 60 秒（配置读取沿用 10 秒），取消和超时回收进程树。HTTPS 凭据助手限定为 Git Credential Manager，关闭其交互、GUI、调试和跟踪；SSH 固定 BatchMode 与严格主机校验，askpass 失败即返回。需要交互认证或首次 SSH 主机确认时，由用户在应用外完成；不弹登录窗口。stderr 只用于错误分类，原文、URL 和认证数据不进入 UI / 会话日志。

## 来源识别

从 remote URL（优先 origin）提取规范化 host，覆盖 HTTPS、SSH 与 scp 风格。精确规则优先于通配规则，通配按域名标签匹配，`*.example.com` 不匹配 `evil-example.com`。相同规则拒绝重复，重叠规则给出优先级和匹配预览；未知服务与没有 remote 的本地仓库分开显示。来源规则仅改变展示，不改 remote URL。

规则与远程开关同用配置事务；来源编辑、删除立即更新所有行。初始规则可编辑、删除，图标类型先提供 Git / GitHub / GitLab / Server，M5 已使用官方 GitHub / GitLab SVG 路径转换的 WPF Geometry 和项目绘制的 Git / 服务器 / 问号图形；不支持导入自定义图形文件。素材与许可证见[第三方图标说明](../THIRD-PARTY-NOTICES.md)。通配后缀重叠时选最长后缀；预览包含当前草稿，不保存 URL、不访问网络。主机比较忽略大小写、规范化 IDN 和末尾点；完整 remote URL 仅在 Git 适配器短暂存在。

## 设置、主题与登录启动

深浅主题使用独立资源字典，控件以 DynamicResource 读取语义颜色，状态同时保留文字。应用缩放使用共享 LayoutTransform，与系统 PerMonitorV2 DPI 叠加；主面板和模态窗口按当前工作区限宽限高，滚动区域宽度约束在视口，狭窄屏幕允许水平滚动。关闭模态窗口恢复触发控件焦点。

登录启动由可注入 IStartupRegistration 适配。生产写 HKCU 的 `Software\Microsoft\Windows\CurrentVersion\Run`，只登记当前用户与 profile 对应值；完整命令不超过 Windows 规定的 260 字符，参数引用并处理根路径末尾反斜杠。登记失败不给成功状态，关闭遇到其他程序位置的命令时保留并提示。普通二次启动激活主实例，`--minimized` 二次启动直接退出；初次登录启动不抢焦点。测试替身不接触真实 Run 键。

依据：[Run / RunOnce](https://learn.microsoft.com/en-us/windows/win32/setupapi/run-and-runonce-registry-keys)、[WPF 动态资源](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/systems/xaml-resources-overview)。

## 语言资源与默认选择

2026-10-17 增加 `Core/Localization` 资源层，内置 249 条英文基准资源及对应简体中文资源。使用框架自带 ResourceManager / RESX；Desktop 通过 XAML 标记扩展和同一文本接口取文案，格式参数独立于翻译，资源缺项回退英文。资源完整性与占位符由测试核对，无额外运行库依赖。

schema 4 的 preferences 增加可选 `language` 字段，值为 `system`（默认）、`zh-Hans` 或 `en`。旧配置缺字段时默认跟随系统；读入未知可选语言代码时回退 system，保留其他配置，不把整个列表判为损坏。UI 保存前仍校验选择是否合法。

启动时先读取配置，再将启动线程的 CurrentUICulture 作为系统显示语言输入，解析本次应用语言后创建窗口和后台采集。当前实现固定本次运行语言，修改只影响下次启动；保存 system 而不是解析后的语言，确保以后仍能跟随系统。数字和日期的区域格式不被语言设置改写，Git 子进程继续使用原有 LC_ALL / LANG=C 协议环境。

系统分组使用翻译后的显示名，原有保留名称及稳定 groupId 规则保持不变；用户文本不查翻译表、不重写。Windows 原生对话框系统按钮遵循 Windows 自身语言设置。

## 性能与发布边界

不沿用初始候选表中未经本项目测量的内存或体积数字。使用固定规模的隔离测试集测量 UI、应用进程和 Git 子进程的总成本，记录硬件、仓库规模及窗口状态，再形成发布门槛。具体协议见开发工作区的验收说明。

2026-10-17 已完成固定 20 仓库的两轮本机测量和回归门槛；持续变更和远程失败仍受本地并发 2 / 远程串行约束，退出无残留后代进程。入口为 `tests/run-performance.ps1`，门槛保存在 `tests/performance-budgets.json`。机器、仓库规模、CPU 口径及短时资源稳定性的限制见 [M6 性能验收](../devSchedule/桌面应用开发/doc/M6性能验收.md)，不将这组基线推广到大型仓库或全天运行。

目标环境为 Windows 10 / 11 的桌面使用场景，兼容结论按实际测试矩阵记录。M1 已在 Windows 10 22H2 的两块 96 DPI 显示器验证窗口生命周期和跨屏定位；Windows 11、物理高 DPI、自动隐藏任务栏等组合尚未验证。发布前复核所选系统与运行时的支持条件。M6-02 已建立 Windows x64 自包含便携 ZIP：运行时随包分发，Git 外置，配置继续保存在独立 profile。升级时退出并解压到空目录；迁移路径需要更新自启登记，卸载前手动关闭自启，删除程序目录保留外部配置。没有 MSI、自动升级或自动卸载服务；当前包验收见 [M6 交付验收](../devSchedule/桌面应用开发/doc/M6交付验收.md)，系统支持、实机及模拟 DPI 的边界见[兼容性与发布说明](兼容性与发布说明.md)。
