# RepoTracker 安装与升级

从 0.5.0 起，推荐分发 `RepoTracker-<版本>-win-x64-Setup.exe`。这是当前用户安装版，包含 .NET / WPF 运行时；Git 仍需另行安装并加入 PATH。安装向导支持简体中文和英文，不需要管理员权限。

## 安装和使用

首次运行安装包可选择程序目录，默认 `%LOCALAPPDATA%\Programs\RepoTracker`。本项目维护者本机使用 `E:\Apps\RepoTracker`。安装后在开始菜单搜索 RepoTracker；Windows“设置 → 应用”中也会出现版本和卸载入口。

应用运行时只显示托盘图标，展开面板也不占任务栏。单击托盘打开，右键可打开设置或退出。托盘是否收进小箭头由 Windows 的显示偏好决定。

程序与数据分开：仓库、分组、语言和设置仍保存在 `%LOCALAPPDATA%\RepoTracker`，或启动参数 `--profile` 指定的目录。安装、升级和卸载都不删除这些数据，也不修改被跟踪仓库。

## 更新版本

直接运行新版 Setup，安装器会识别已有应用并使用原目录，更新系统中的同一条应用登记。已安装时不允许用 `/DIR` 换到另一目录；不会为每个版本创建新的程序路径。相同版本可以重新安装修复，较旧版本会被拒绝。

更新前完成设置或添加仓库窗口中的操作。安装器通过 Windows Restart Manager 正常关闭占用程序文件的实例；有未完成编辑时应用可以拒绝关闭。成功更新后，已登记重启的实例可恢复到原 profile 并收起到托盘。Windows 对刚启动不足 60 秒的实例可能不执行自动恢复；可在安装完成页勾选“启动 RepoTracker”，或从开始菜单打开。

登录自启保持原来的开关和路径，不会因安装而自动开启。更新时校验原包清单，移除已不再分发且内容未变的旧文件；未列入清单的个人文件不作为清理目标。不要把配置或仓库放进程序目录。

这套流程由用户运行新版安装包触发，目前没有后台联网下载更新服务。固定安装标识为 `Septim.RepoTracker`，应用路径登记在当前用户的 Windows `App Paths` 中；不会增加系统 PATH。

## 从旧便携版或开发版本迁移

1. 从旧版本托盘菜单退出；收起不等于退出。保留原数据目录，必要时备份 `state.json` 和 `state.json.bak`。
2. 安装到新的空程序目录。不要直接覆盖工程 `bin` 或混有个人文件的便携目录。
3. 从开始菜单运行；默认 profile 会自动读回原有设置。自定义 profile 仍需用相同 `--profile` 参数启动。
4. 若旧版已开启登录自启，应在旧版关闭后迁移，在安装版重新开启；已有自启值属于同一 profile，不能同时保留两个路径。

以后均使用 Setup 更新同一安装位置。旧源码、便携 ZIP 不会被安装器遍历删除；不再使用的旧便携文件可自行保留备份或移除。

## 卸载

从托盘退出应用，在 Windows“设置 → 应用”中卸载 RepoTracker。卸载移除程序、开始菜单快捷方式、应用路径和卸载登记，并仅清除指向该安装 exe 的 RepoTracker 登录自启项。外部 profile、跟踪仓库与其他程序的自启项保持不变。应用运行中会提示先退出，避免不完整卸载。

## 分发与构建

发布物包括 Setup、对应 `.sha256` 和 `installer-manifest.json`；保留 ZIP 供便携使用与诊断。安装包尚未做代码签名，系统可能提示未知发布者；不要把有安装器等同于已获得 Windows 信誉或完成所有平台验收。支持范围见[兼容性与发布说明](兼容性与发布说明.md)。

构建入口 `publish-win-x64.ps1` 默认生成 ZIP 和安装包，`-PortableOnly` 只生成 ZIP。安装器使用固定版本 Inno Setup 7.1.0，可通过 `-CompilerPath` 指定已安装的 `ISCC.exe`。已有通过校验的程序目录也可交给 `build-installer.ps1 -PackageDirectory <目录>` 生成 Setup。编译器不随应用分发。项目图标由 `tools/Export-AppIcon.ps1` 从已有 WPF 图形导出，exe、快捷方式和安装包使用同一图标。
