# RepoTracker 交互设计

> 公开版本说明：本机环境信息已脱敏，示例路径与标识不用于定位原始私有产物。

从 Windows 通知区托盘图标展开仓库面板，以用户手动分组组织仓库状态。2026-10-19 按用户要求取消展开时的任务栏占位，本文记录当前交互基线。开发进度见[桌面开发里程碑](../devSchedule/桌面应用开发/doc/里程碑-桌面应用开发.md)。

## 原型入口与实现边界

Penpot 文件（内部访问地址已省略）的 `RepoTracker / main` 演示从任务栏进入，`RepoTracker / groups` 演示分组操作。画板 26–27 表达任务栏场景，28–39 表达分组及维护流程；其余画板作为添加、状态、来源、设置与主题参考。

原型是预设状态图，不包含任意输入和跨画板的真实持久化。实现必须让全部仓库行都可操作，补齐添加时选组、重复路径提示、来源编辑删除、超长内容滚动及键盘访问，不照搬示例中只有 repotracker 可点击的限制。历史部分结果画板未显示分组，真实应用应保留分组状态。

## 主面板与窗口行为

点击托盘图标展开；标题栏收起、Esc 或系统最小化均隐藏到托盘，展开和收起都不占任务栏或 Alt+Tab，也不留下桌面最小化标题条。默认失焦收起，设置、菜单与文件选择流程不误收起。图钉表示“保持展开”；退出放在应用内菜单和托盘菜单中。

运行时仅保留通知区图标；单击托盘或键盘激活打开面板，右键提供打开、设置、退出。已有模态窗口时优先回到该窗口，托盘设置与退出暂不可用，避免打断保存或重复打开设置。取消托盘菜单不展开已收起的面板。再次运行程序会恢复已有面板；退出仍结束应用。

图标是否出现在右下角小箭头内由 Windows 和用户控制。在“检查与窗口”页说明可拖出图标或在系统任务栏设置里开启显示，不承诺程序能强制始终显示在外面。登录自启默认关闭，每台电脑单独登记，托盘功能不会自动开启自启。

主面板保留来源、名称与路径、分支、工作区及上游比较、快捷操作各列。顶部依次提供本地刷新、保持展开、设置、菜单、收起；列表上方放新建分组和管理分组；底部保留添加仓库及本地检查时间。仓库行提供打开目录、解除跟踪及移动分组，动作须有可访问名称和悬停说明。

深色为首轮落地基准，浅色对照随主题适配验收。设计基准宽 760，仓库行高 68；六仓库三组全部展开时内容高 760。实际窗口受显示器工作区约束，列表超长时滚动内容，标题、列标与底部入口保持可用，不能按截图尺寸溢出屏幕。文字缩放、截断提示、焦点、点击区域与屏幕阅读器名称需在真实 WPF 中验收。

## 仓库与分组操作

| 操作 | 结果与异常反馈 |
|---|---|
| 添加仓库 | 选择或输入目录、校验仓库、选择分组后保存；默认未分组，重复路径定位到已有条目，失败不插入半成品记录 |
| 移除跟踪 | 确认所选仓库，仅删除跟踪记录；支持当前会话撤销，原分组失效时回退未分组；不删文件 |
| 新建组 | 输入合法且不重复的名称，可创建空组；规则详见技术设计 |
| 改名 | 保留稳定 ID、成员与顺序，校验失败留在表单并保留输入 |
| 移动分组 | 在该仓库的操作中选择目标组，当前组明确标识；移动后只出现一次，数量立即更新 |
| 删除组 | 确认组名和成员数，成员全部回到未分组并继续跟踪；系统未分组不能删除 |
| 折叠组 | 标题显示仓库总数，折叠不暂停采集；重启后恢复折叠状态 |

采用单层、单归属；自定义组按创建顺序，未分组最后。不做自动分组、嵌套和拖动排序。打开目录不可用时给出原因；不可达仓库仍可移组或解除跟踪。

## 状态语义

| 场景 | 必须呈现 |
|---|---|
| 有工作区修改 / 干净 | `●` / `✓` 加状态色，完整文字保留在悬停和无障碍名称中 |
| 领先 / 落后 | `↑n` / `↓n` 表示相对本地已知上游的提交数；未知为 `?`，不填 0，数据时间在悬停提示中 |
| 未设置上游 | `—`，悬停说明当前分支未指定比较目标，不表示没有远程仓库，不代替用户设置 tracking |
| 分离 HEAD / 初始未提交 | 显示相应文字与可用的短 SHA，不伪造普通分支或同步状态 |
| 不可达 / 非仓库 / 冲突 | `!`，保留条目，悬停说明原因或冲突数，不自动删除记录 |
| 远程失败 | 远程标记为 `!`，保留最近成功结果及时间，本地检查继续 |
| 主动关闭远程 / 从未检查 | 关闭时不显示远程标记，面板底部和悬停说明已关闭；开启后未检查显示 `?`，检查中 `…`，成功 `↻`，跳过 `—` |

列表状态使用紧凑图标，分支列适当加宽。检查时间与错误详情移入悬停提示，表头提供图例；超过 999 的提交计数显示 `999+`，悬停仍为准确数字。右键菜单、子菜单和分组展开箭头使用应用主题模板，避免系统图标栏在深色主题中出现白色竖条；保留菜单的勾选、快捷键、禁用和焦点反馈。

## 手动添加子仓库

主列表在每个手动分组内，按工作树目录关系建立可展开层级。子仓库挂在同组最近的已跟踪祖先下，中间普通目录保留在行名称的相对路径中；完整路径可悬停查看。父仓库显示后代仓库数量，左侧箭头支持点击及键盘 Tab / Enter 操作。右侧状态仅表示当前仓库；下方单独显示“子仓库”汇总，不把后代计数相加成父仓库状态。

汇总统计同组树中所有层级的后代，展开、折叠时均显示。`●n`、`↑n`、`↓n` 分别表示有未提交、待推送、待拉取的仓库数，同一仓库可出现在多项中；`!n` 表示冲突或本地检查失败，`?n` 只表示尚未取得完整状态。`—n` 单独统计当前分支未设置上游，或分离 HEAD / 尚无提交等不可比较情况，悬停区分原因。已知全部后代工作区干净时显示 `✓`，与推拉比较状态分别显示；只有已知上游也一致时才提示全部同步。检查失败时历史已知变化仍可保留，同时显示异常。隐藏后代仍随状态刷新更新汇总，移组或移除后重新按实际树关系统计。

仓库展开按钮使用 24 × 24 的独立箭头样式和 28 宽列，来源图标为 32 × 32，与箭头垂直居中，名称前保留 8 的间距；每层缩进 20。点击不残留高窄外框，键盘导航仍保留焦点提示。展开、折叠和应用内 150% 缩放均使用相同布局规则。

新记录默认展开，折叠状态跨重启保存，折叠不暂停本地或远程检查。重复添加隐藏条目时，会展开所属组及全部祖先并定位。移组、移除仍只作用于当前记录：后代保留跟踪，重新挂到同组最近祖先或分组顶层；不会随父仓库移组或删除。不同手动分组之间不建立展开关系。

普通“添加仓库”表单仅添加指定路径对应的仓库，不扫描目录。父仓库行菜单提供“添加子仓库…”：表单说明父仓库完整路径，可输入完整路径或浏览选择；文件选择器从父仓库目录开始。新增记录沿用父仓库当前分组。选中的工作树根必须严格位于父仓库目录内；父仓库本身、属于父仓库的普通文件夹和其他目录的仓库会显示错误并保留输入。也可通过普通添加入口直接指定子仓库及分组。

两种入口都按真实工作树根路径在全部分组内去重，兼容大小写、末尾分隔符、普通子目录与 junction 别名。重复添加时提示并展开定位已有记录，不改变其分组；相同仓库名或相同 commonDir 不视为重复。取消不修改清单；校验或保存失败保留表单与输入，保存成功后才更新主列表。已有父子仓库记录和折叠状态可直接沿用，无需迁移配置。

支持手动指定普通嵌套仓库、已初始化子模块和 `.git` 文件形式的工作树；不遍历目录或初始化子模块。每个添加的仓库独立检查改动和本地已知的 ahead/behind；远端信息更新仍由已有远程检查开关控制。

## 设置与反馈

检查与启动页管理本地间隔、并发数、远程开关和间隔、自启；输入非法值时解释范围。首次远程检查默认关闭，主动开启时说明会更新 Git 元数据。来源页支持添加、编辑、删除与主机匹配预览，内置规则的可编辑边界须在实现时明确呈现。设置保存后立即反馈，失败不伪装成功。

M4 已提供“检查与窗口”和“来源规则”两个页签。前者提供持久化远程开关、作用范围说明与立即检查远程入口；顶部刷新仍仅刷新本地。后者允许编辑或删除所有规则（含初始 GitHub / GitLab），保留非法输入并给出错误；草稿预览显示命中的主机和规则，不发网络请求。来源列使用 GitHub / GitLab 官方矢量图标和本地 / 自建 / 未知图形，主面板行内区分远程关闭、从未检查、检查中、跳过、失败与成功时间，悬停查看最近远程成功和原因。M5 已加入本地 5–300 秒、远程 1–120 分钟、本地并发 1–4，以及深浅主题、100% / 125% / 150% 应用缩放。“保存检查与外观”即时应用；关闭未保存的数字 / 外观草稿不改配置。保持展开、远程和登录启动开关分别立即保存，失败复原开关并显示原因。登录启动隐藏到托盘，重复登录启动不激活已有窗口；开关依据系统登记，测试使用隔离适配。

真实原型以用户输入和状态结果为准：关闭弹窗不丢已有列表，删除和移除的文案始终说明对象与作用范围；菜单、对话框和长列表可通过键盘操作。窗口移动、多 DPI 与工作区定位按[技术设计](技术设计.md)验证。

## 界面语言

2026-10-17 追加多语言要求。首次使用和旧配置默认“跟随系统”，以启动时 Windows 显示语言为准，首批支持简体中文和 English。英文变体统一使用 English；简体中文变体使用简体中文，其他语言（当前含繁体中文）回退 English。保持“跟随系统”时，每次启动重新判断，系统语言变化后需重新启动应用。

设置的“检查与窗口”页提供“界面语言”：跟随系统 / 简体中文 / English。用独立的“保存语言”按钮保存，明确提示下次启动生效；其他检查和外观设置仍即时应用。语言保存失败时保留旧配置与选择草稿，关闭未保存的选择不改变配置。

主面板、菜单、弹窗、状态、校验错误、提示与可访问名称使用同一语言。语言名使用自称，便于切回。仓库、分支、自定义分组和来源名称保持原样；系统未分组仅切换显示名，归属仍以空 groupId 表示。Windows 原生文件夹选择器的系统按钮由 Windows 决定语言，应用提供的标题参与翻译。
