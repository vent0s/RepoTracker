# 开发与运行

> 公开版本说明：本机环境信息已脱敏，示例路径与标识不用于定位原始私有产物。

当前可运行任务栏窗口，管理真实 Git 仓库及手动分组，持续查看本地状态和来源，并可主动开启远程检查。首次启动为空列表且远程关闭；仓库、分组、来源规则、检查间隔、并发数、主题、缩放和保持展开自动保存。进度与实际验收边界以[开发里程碑](../devSchedule/桌面应用开发/doc/里程碑-桌面应用开发.md)为准。

## 环境和构建

使用 Windows 和 .NET SDK **10.0.201**，`global.json` 禁止隐式跨版本回退。框架依赖版程序需要 .NET 10 Windows Desktop Runtime；10-16 验收使用 10.0.5，10-17 本机使用 SDK 10.0.401 / Runtime 10.0.12 做显式兼容验证，未重新验证锁定 SDK。当前便携发布包包含固定的 10.0.13 运行时。版本不表示最新版本或最终系统支持承诺。

在仓库根目录执行：

```powershell
dotnet restore RepoTracker.slnx --locked-mode
dotnet build RepoTracker.slnx --configuration Release --no-restore
dotnet run --project src/RepoTracker.Desktop --configuration Release --no-build
```

也可以直接启动 `src/RepoTracker.Desktop/bin/Release/net10.0-windows/RepoTracker.Desktop.exe`。目录里的 DLL 和运行时配置需要一起保留；这是开发构建，独立便携包使用下方发布入口。

依赖版本由 `Directory.Packages.props` 集中维护，七个项目均保留 `packages.lock.json`。生产代码目前只使用 .NET / WPF 自带库；测试依赖 Microsoft.NET.Test.Sdk 18.0.0、xUnit 2.9.3、VS runner 3.1.5。仓库 `NuGet.Config` 只指定 nuget.org，避免继承其他项目的私有源；不改用户全局配置。需要升级依赖时明确更新版本及 lock，再验证锁定恢复。

## 窗口操作

| 操作 | 行为 |
|---|---|
| 任务栏应用按钮 | 使用标准 Windows 激活、恢复和最小化行为 |
| 标题栏减号 / Esc | 最小化收起，保留任务栏入口 |
| 图钉 / Ctrl+Shift+P | 切换保持展开并保存，重启恢复；固定任务栏快捷方式由 Windows 管理 |
| 设置 / Ctrl+, | 打开检查与窗口、来源规则页；保存立即生效，完成或 Esc 关闭 |
| 添加仓库 / Ctrl+O | 输入绝对目录或浏览选择文件夹，选择所属分组，校验 Git 工作树后保存 |
| 新建分组 / 管理分组 | 创建空组；管理时显示各组改名、删除入口，未分组受保护 |
| 仓库行更多菜单 | 移动到任意组或未分组；移除跟踪前确认，之后可撤销最近一次移除 |
| 仓库行文件夹按钮 | 用系统资源管理器打开该工作树根目录 |
| 分组标题 | 展开或折叠真实列表，自动持久保存 |
| 顶部刷新按钮 | 将全部仓库加入本地检查队列，不连接远程；检查期间仍可管理仓库 |
| 更多 → 退出 / Alt+F4 | 结束应用及单实例监听 |

默认失焦收起。菜单和模态对话框通过可释放的焦点保护避免误收起，对话框关闭后恢复默认行为。保持展开、主题、缩放与分组折叠跨重启保存；拖动位置仅在当前会话有效。撤销最近一次移除仅在当前会话有效，原分组已删除时恢复到未分组。

窗口首次出现在当前前台窗口所在显示器的工作区边缘；恢复时保留本次会话位置并重新约束在工作区内。没有获取任务栏应用图标的精确矩形，也没有 Explorer 注入。自动隐藏任务栏未预留工作区时，采用右下角边缘位置。

单实例以当前用户和规范化 profile 路径隔离，用本地命名互斥量及仅允许当前用户的命名管道传递唤醒请求。第二实例通过管道取得真实主进程 ID，按 Windows 规则授予前台激活权限；系统仍可能拒绝后台抢焦点。没有切换顶置来强制抢焦点。默认 profile 为 `%LOCALAPPDATA%/RepoTracker`，包含 `state.json`、备份和有上限的会话日志。

## 外观与登录启动

“检查与窗口”页可保存深色 / 浅色主题和 100% / 125% / 150% 界面缩放，主面板与已打开的设置同时生效。缩放与系统 DPI 叠加，窗口尺寸受当前显示器工作区限制；内容不足时滚动中部，保留标题和底部操作。名称、路径、分支和错误有完整提示，表单支持 Tab、Enter 和 Esc，关闭弹窗后返回原焦点。

“登录 Windows 时启动”开关登记当前用户的 Run 项，值名按 profile 隔离；启动命令包含已引用的 exe、绝对 profile 和 `--minimized`。Windows 登录后收起到任务栏，用户可点击展开。开关状态读自系统登记，不在 JSON 重复保存，不会在每次运行时重新注册。路径过长或权限失败会提示；关闭时不会删除来自另一程序位置的同名启动项。安装位置移动后需重新登记，Windows 中的禁用策略仍由系统管理。当前开发版运行路径不是最终安装位置。

测试通过注入的隔离启动项存储验证开关和持久化，**不写本机真实 Run 项、不注销或重启 Windows**。M6-02 另验证便携目录迁移 / 删除后的配置保留，以及自启适配在同路径升级、迁移路径和关闭时的归属保护；真实 Windows 登录仍未验证。

## 界面语言

首次启动和旧配置默认跟随 Windows 显示语言，当前提供简体中文和 English。未支持的系统语言回退 English。系统显示语言与数字 / 日期区域设置分开：仅切换应用文案，不改区域格式。

在“设置 → 检查与窗口 → 界面语言”选择“跟随系统 / 简体中文 / English”，点击“保存语言”。保存后退出再打开应用生效；保存失败保留之前设置。跟随系统时，系统语言变化后也需重新启动应用。用户创建的名称与仓库路径保持原样。

2026-10-17 的多语言和桌面回归使用本机 SDK 10.0.401 / Runtime 10.0.12 做兼容验证，项目仍锁定 10.0.201。默认构建命令仍要求锁定 SDK；本轮替代环境与实际命令见[M5 多语言验收](../devSchedule/桌面应用开发/doc/M5多语言验收.md)，不把替代 SDK 通过视为原锁定 SDK 已复验。

## 仓库与配置

添加需要 PATH 中可访问的 Git for Windows；2026-10-17 性能场景使用 Git 2.56.0.windows.2，10-16 历史功能验收使用 2.51.0.windows.1。可选择仓库子目录，最终保存规范化后的工作树根、gitDir 和 commonDir；目录大小写、junction 别名和子目录会去重，共用 commonDir 的不同 worktree 各自保留。重复添加会展开所属组并定位已有行。本地层使用 `rev-parse`、`status` 与 `config` 读取，不自动扫描磁盘，不修改 Git 配置、引用、索引或仓库文件；主动开启后的远程 fetch 会更新允许范围内的 Git 元数据。

每次操作先原子保存，再更新界面。`state.json.bak` 保留上一个有效快照；损坏 JSON 会先另存为 `state.corrupt-*.json`，然后尝试恢复备份，没有备份时显示带明确提示的空列表。读取失败、无法保存损坏副本、备份损坏或未来 schema 会禁止修改，原文件保留。配置被外部改动后，当前进程拒绝覆盖，重启读回后再操作。保存失败会保留原列表与表单输入；不要通过清空 profile 解决权限问题。

当前 schemaVersion 为 4。schema 1 / 2 升级后远程保持关闭、加入默认来源规则；schema 3 保留用户明确保存的远程开关与规则，新增设置使用默认值。规则和开关跨重启保存，本地与远程状态快照仅存内存，重启重新检查。模型与兼容范围见[技术设计](技术设计.md#数据与配置)。目录后来不可达时仍保留记录与上次成功时间，仍可移组或解除跟踪；目录恢复后下一次检查会恢复正常状态。

## 本地状态检查

默认每次检查结束后 15 秒再次检查，最多 2 个检查并发，任务启动间隔至少 100ms；文件变化会在 400ms 去抖后提前检查，持续变化最多延后 2 秒。工作树与实际 Git 元数据目录均被监听；监听不可用时保留定时兜底，并在行提示中说明。设置支持本地 5–300 秒、远程 1–120 分钟、本地并发 1–4，保存后无需重启。降低并发时让正在执行的检查完成，再按新上限派发；不延后已排队的文件变化。

分组折叠、面板最小化均不停止采集。刷新期间保留当前结果；失败显示原因及上次成功时间，不把未知状态写成干净，也不填零。悬停状态区域可见暂存、未暂存、未跟踪项和冲突数量。无上游、分离 HEAD、未首次提交有各自文字；领先 / 落后只表示本地已知上游关系，不代表实时远端。来源 remote 可能与当前分支的 upstream 不同，远程成功不等于所有上游均已同步。

检查固定使用记录的 gitDir 和 worktreeRoot，避免 `.git` 失效后向上找到其他仓库。退出先取消并等待检查回收；移除仓库取消其检查并丢弃晚到结果，立即重加同一工作树也不会与旧检查重叠。睡眠消息会暂停检查，恢复时错峰重查；逻辑已经测试，尚未触发物理睡眠验收。

## 来源规则与远程检查

来源随本地检查读取：优先 origin，否则按 remote 名称排序选择第一个；没有 remote 显示“本地仓库”，有 remote 但无法匹配显示“未知服务”。初始包含 GitHub / GitLab，可以在设置中添加、编辑、删除，包括初始规则。主机名可写 `code.example.com` 或 `*.example.com`，精确匹配优先，通配取最长后缀且不包含根域。预览使用当前草稿，显示命中原因，不连接网络或保存输入 URL。图标使用 GitHub / GitLab 官方矢量路径，以及 Git、服务器、问号图形；可选内置类型，不支持导入图形文件。来源和许可见[第三方图标说明](../THIRD-PARTY-NOTICES.md)。

远程检查首次及 schema 1 / 2 升级后关闭。阅读设置中的作用范围后勾选开启，默认每 10 分钟排队执行（可设置为 1–120 分钟）；相邻任务间隔至少 1 秒，全局串行，最多执行 60 秒。立即检查远程只在开启后可用；顶部刷新仍为本地检查。关闭、移除仓库、退出或睡眠会取消相应任务，本地检查不依赖远程结果。检查时间按本次运行记录；远程失败保留上次成功时间与本地已知计数，详情见行内悬停提示。

只支持单一 HTTPS / SSH / scp URL，以及单一 heads 到对应 remote-tracking 的同名映射。多 URL、mirror、URL 重写、自定义 upload-pack、非标准 refspec、带密码或查询参数的 URL、本地路径等会跳过并解释。不会自动改写这些配置。fetch 下载对象并更新远程跟踪引用，禁用 tags、prune、子模块递归、hooks、FETCH_HEAD 和自动维护；不提交、推送、修改本地分支或 upstream。

HTTPS 使用 Git Credential Manager 的已有非交互凭据；SSH 使用已有密钥 / agent 与已确认主机。需要登录、密码或主机确认时检查失败，不弹登录窗口；可先在应用外完成认证，再通过设置重新检查。完整限制见[技术设计](技术设计.md#git-状态与采集)。

## 隔离测试与诊断

```powershell
dotnet test RepoTracker.slnx --configuration Release --no-build --logger trx --results-directory tests/artifacts/results
```

桌面测试需要已登录、可交互的 Windows 桌面，会短暂显示测试窗口、设置和目录选择器，并在两个测试进程之间切换焦点，结束后自动退出。它不是无头测试。普通受限沙箱可能只暴露主显示器并使 `GetForegroundWindow()` 始终返回 0，此时应在允许访问交互桌面的执行环境运行桌面测试；不得将这种运行结果记为失焦行为通过。

可单独运行无需桌面交互的测试：

```powershell
dotnet test tests/RepoTracker.Core.Tests --configuration Release --no-build
dotnet test tests/RepoTracker.IntegrationTests --configuration Release --no-build
dotnet test tests/RepoTracker.Desktop.Tests --configuration Release --no-build --logger trx --results-directory tests/artifacts/results
```

桌面测试在 `tests/artifacts/<run-id>/` 保存 `report.json`、`reload-report.json`、`minimized-report.json`、主面板与表单 PNG、独立 profile 日志。六个小型 Git 夹具会通过真实表单添加、移组、改名、删组、移除撤销，再退出并启动新进程验证恢复。M5 还加入 20 仓库 / 7 分组长列表、100% / 125% / 150% 应用缩放和 800×600 受限视口；应用缩放与早期 150% / 200% PNG 渲染采样均不代表真实系统 DPI 已验证。`RepoTracker.Desktop.TestHost` 只承担测试编排，加载真实 `App`、窗口和命令；第二实例使用真正的产品 exe。产物已被 Git 忽略。

Git 夹具在当前项目的测试目录内构造分离 HEAD 和最小对象；linked worktree 使用独立 gitdir / commondir 结构。不创建命名分支、upstream 或工程副本，应用管理前后对夹具文件和 Git 元数据做哈希比较。夹具源代码位于 `tests/Shared`，不依赖 devSchedule。`.gitignore` 覆盖 bin / obj、测试产物、编辑器状态、`.artifacts/`、根目录 `publish/` 与 `.local/`；保留 package lock、源码及正式验收证据。

需要手动诊断时，可用绝对路径指定另一份 profile：

```powershell
dotnet run --project src/RepoTracker.Desktop --configuration Release --no-build -- --profile "E:\Projects\repotracker\tests\artifacts\manual-profile"
```

同一 profile 再次正常启动会唤醒已有实例；带 `--minimized` 时收起启动，已有实例不会被再次激活。不同 profile 可以独立运行。此参数只改变应用自身的数据与日志位置，不能用来指向其他软件的数据目录。日志不记录所选完整目录或认证数据。

自动化结果和未覆盖组合见 [M1 验收记录](../devSchedule/桌面应用开发/doc/M1验收记录.md)、[M2 验收记录](../devSchedule/桌面应用开发/doc/M2验收记录.md)、[M3 验收记录](../devSchedule/桌面应用开发/doc/M3验收记录.md)、[M4 验收记录](../devSchedule/桌面应用开发/doc/M4验收记录.md)与 [M5 验收记录](../devSchedule/桌面应用开发/doc/M5验收记录.md)。M4 网络测试仅连接本次测试自有的回环端点；成功 fetch、认证失败和离线通过进程替身验证，未使用真实服务或凭据，未创建分支或 upstream。

## 性能测量

先构建 Release，再在已登录的 Windows 桌面使用 PowerShell 7 运行：

```powershell
pwsh -File tests/run-performance.ps1 -Smoke
pwsh -File tests/run-performance.ps1
pwsh -File tests/run-performance.ps1 -CheckBudgets
```

短流程检查编排；正式测量约 11 分钟，另外需要创建夹具的时间。`-CheckBudgets` 完整复跑后检查当前固定数据集的回归门槛。运行会短暂展开测试窗口，并保留新的 `tests/artifacts/performance-*/` 目录，不读写用户 profile 或真实仓库。固定 20 仓库、5,020 个工作树文件约 16.6 MiB；持续变更由独立写入器产生，远程阶段只连接测试自有回环 HTTPS 端点并模拟连接失败。

输出包括机器和数据集信息、逐秒采样、检查事件、分阶段 CPU / 内存 / 子进程 / UI 响应、写入数量和退出回收结果。CPU 包含应用及已退出的 Git 子进程；子进程内存峰值是每秒采样下界。正常结束会停止写入器和应用；异常时也仅清理本轮拥有的进程。不要同时运行其他仓库测试来干扰测量。

当前机器与固定数据集的基线、数值门槛和完整复验结果见 [M6 性能验收](../devSchedule/桌面应用开发/doc/M6性能验收.md)。在不同硬件、Git 版本或仓库规模下，应重新测量并审阅门槛。

## Windows x64 便携包

在 PowerShell 7 中执行：

```powershell
pwsh -File publish-win-x64.ps1
# 仅当明确进行工具链兼容验证时指定本机 SDK；不会更改 global.json。
pwsh -File publish-win-x64.ps1 -SdkVersion 10.0.401
# 先构建 Release 测试宿主，再对上一步产生的 ZIP 验收。
pwsh -File tests/run-package.ps1 -PackageZip "publish/<本次目录>/RepoTracker-0.4.0-preview.2-win-x64.zip"
```

脚本在新的 `publish/<时间戳-随机后缀>/` 中建立独立 SDK 工作目录和中间产物，锁定恢复生产依赖，输出 self-contained / win-x64 / Release 文件夹和 ZIP；不裁剪、不合并单文件，不覆盖旧包。三份生产 package lock 包含 win-x64，普通工程恢复和发布恢复共用同一锁定输入。默认要求 SDK 10.0.201，缺少时明确失败；兼容构建会在清单中记录实际 SDK。

包内包含 CoreCLR / WPF 10.0.13、英文中性资源、简体中文卫星资源、使用说明、兼容矩阵、依赖清单及原文许可。`package-manifest.json` 记录版本、SDK、运行时、源码提交及 dirty 状态、逐文件 SHA-256 和 runtime / host 包的 NuGet SHA-512；ZIP 旁另有整体校验值。版本来自 Desktop 项目，当前为未签名的 `0.4.0-preview.2`。这些入口可重复构建，时间戳和 ZIP 元数据不同，不承诺 ZIP 字节完全一致。Git 是外部依赖，不随包分发。
