# RepoTracker 第一版原型规格

> 公开版本说明：本机环境信息已脱敏，示例路径与标识不用于定位原始私有产物。

原型围绕“点击任务栏应用按钮，展开仓库状态面板，然后收起继续工作”设计。2026-10-16 按用户反馈将主入口调整为 Windows 任务栏应用区的 RepoTracker 图标；用户确认该方向后追加手动分组。它是 Windows 桌面面板，不引入网页管理后台式侧栏、账户或提交历史。

打开 Penpot 文件（内部访问地址已省略）。页面名为 `01 · RepoTracker 产品原型`。进入演示模式后选择 `RepoTracker / guide` 或 `RepoTracker / main`；main 从任务栏收起状态开始。也可从 empty、offline、light、menu 入口评审独立场景。

## 视觉约定

默认面板 760 × 590，6 个仓库每行 64。首次添加完成的面板收短至 760 × 350，七仓库结果稿为 760 × 654。以逻辑像素讨论尺寸；正式桌面窗口还需验证缩放和屏幕工作区约束。

深色底 `#171A21`、行背景 `#20252E`、强调色 `#8AB4FF`；浅色对照底 `#F8F9FC`。外框圆角 14，按钮圆角 7，图标命中区域 32 × 32。颜色和文字共同表达状态，避免只靠颜色区分。标题主要 18–24，正文 13–14，状态与辅助信息 10–12。中文采用 Noto Sans SC，英文 Inter，分支 Roboto Mono；WPF 落地可用系统字体匹配，但必须重新验收换行与密度。

仓库行按来源、名称和路径、分支、工作区与同步状态、操作排列。标题栏集中放本地刷新、保持展开、设置、应用菜单和收起；添加入口固定在底部。图钉表示关闭失焦自动收起，与系统“固定到任务栏”是两个动作。GitLab 标识为简化矢量稿，正式发布前核对官方品牌资产。

任务栏场景为 1440 × 900，底部任务栏高 64；分组前的展开面板为 760 × 590，增加分组后为 760 × 760，底部仍位于任务栏上方。任务栏外观与图标位置是示意，不能视为已实现精确锚定。窗口生命周期、系统固定及定位边界见[选型依据](概述.md#任务栏入口合同)。任务栏修订的历史导出：[收起](../design/evidence/taskbar-closed.png)、[展开](../design/evidence/taskbar-open.png)；当前分组外观见[主面板](../design/evidence/groups-main.png)。

原生资产包含 6 个状态组件和深浅两套颜色。首轮画面使用原生形状与文字，不是把整张 PNG 导入画布。现有状态行尚未全面改为共享组件实例；后续多轮视觉调整时可收敛实例与变量绑定。

## 手动分组

主面板使用分区标题组织仓库，标题包含组名、仓库数和折叠箭头。首轮为单层分组，一个仓库只属于一个分组；默认进入“未分组”。示例为工作 3 个、个人 2 个、未分组 1 个。自定义分组按创建顺序显示，未分组在最后；排序、嵌套与自动归类不纳入本轮。

“新建分组”和“管理分组”放在列表上方。仓库行的移动图标进入分组选择；当前原型以高亮的 repotracker 行演示，保留原有打开目录和移除跟踪。所有分组变化只修改 RepoTracker 配置，不移动磁盘目录，不改 Git 配置，折叠不暂停检查。

新建允许空组；名称 trim 后为 1–30 个字符，不允许重复。管理中可改名或删除自定义组。删除前明确影响数量，确认后仓库回到未分组，仍然跟踪；未分组不能改名或删除。添加仓库时选择分组属于正式实现要求，当前添加向导尚未补分组选择，默认进入未分组。

6 个仓库、3 个全部展开的分组面板为 760 × 760；折叠工作组后高度为 568。新增空组结果稿高 804，用于展示内容变化。正式窗口需受工作区高度约束，内容超长时滚动仓库区域，保留标题与底部操作；该滚动与缩放尚未实现。

## 状态语义

| 状态 | 表达 | 不可误解为 |
|---|---|---|
| 工作区有修改 | 黄色“● 变更” | 一定有未推送提交 |
| 工作区干净 | 绿色“✓ 干净” | 远程已经同步 |
| 领先 / 落后 | “↑ 2”“↓ 1”并显示数据时间 | 服务器实时值 |
| 无上游 | 灰色“无上游” | ahead=0 且 behind=0 |
| 分离 HEAD | 分离状态、短 SHA | 当前存在活动分支 |
| 本地目录不可达 | 红色“路径不可达”，不提供打开目录动作 | 仓库已经被移除 |
| 远程失败 | 保留已知计数，提示离线与截至时间 | 本地检查也失败 |
| 主动关闭远程 | 标明“远程检查已关闭” | 离线错误 |
| 尚未远程检查 | 标明仅本地数据 | 已进行本次 fetch |

图中名称、目录、分支、时间和计数都是演示数据，不是从真实项目采集的状态。

## 点击路径

- main 入口 → 点击任务栏 RepoTracker 图标 → 展开面板 → 再次点击同一图标或标题栏收起 → 返回收起状态；任务栏入口始终可见。
- 默认面板 → 添加仓库 → 浏览 → 校验通过 → 添加 → 7 个仓库。目录输入为预设示例；“检查目录”提供失败分支。
- 空状态 → 添加第一个仓库 → 预设选择后的校验通过 → 1 个仓库。
- 默认面板中 repotracker 的移除 → 确认 → 5 个仓库 → 撤销 → 恢复原列表。其他行的移除图标保留视觉占位，不指向错误仓库的确认框。
- 设置 → 已知来源 → 添加来源 → 保存 → 保存结果 → 4 条来源规则。
- 设置关闭远程检查 → 对应开关关闭画面 → 返回面板 → 显示本地模式。
- 默认面板图钉 → 保持展开状态 → 再点图钉返回。标题栏应用菜单可进入面板、设置、自启演示和退出说明。
- 任务栏展开 → 分组面板，或从 `RepoTracker / groups` 开始。工作组标题 → 折叠 3 个仓库 → 再点标题展开。
- 新建分组 → 示例名称“工具” → 创建 → 显示 0 个仓库的空组。
- repotracker 行移动图标 → 选择“个人” → 工作 2 个、个人 3 个、未分组 1 个，总数仍为 6。
- 管理分组 → 工作组重命名 → 示例名称“工作项目” → 3 个仓库及归属保持原样。
- 管理分组 → 删除个人组 → 确认 → 工作 3 个、未分组 3 个，跟踪总数仍为 6。

当前使用 Penpot 的原生 `click / navigate-to` 连接预设画板，未实现自由输入、任意参数组合或跨所有画面的持续状态。7 个演示入口彼此独立；分组维护只连通上述代表性对象，移动选择的其他选项暂为视觉占位。旧的添加、离线和主题分支仍保留首版未分组结果布局，不能把这些画面当成桌面业务实现。

## 后续设计范围

来源编辑/删除及重叠规则校验、重复仓库提示、超长路径与分支的截断提示、大量仓库滚动、键盘焦点和设置下拉选项仍需下一轮细化。任务栏激活与定位、主面板失焦收起、保持展开后的窗口移动、资源管理器打开、开机启动、真实 Git 查询需要桌面实现后验证。原型不触发这些系统行为，也未修改本机任务栏。

用户于 2026-10-16 已确认任务栏与手动分组方案。本文保留画板与示例映射，当前产品行为以[正式交互设计](../../../doc/交互设计.md)为准；开发进度见[桌面应用开发里程碑](../../桌面应用开发/doc/里程碑-桌面应用开发.md)。原型证据继续保存在[设计记录](里程碑-技术选型与Penpot原型.md)。
