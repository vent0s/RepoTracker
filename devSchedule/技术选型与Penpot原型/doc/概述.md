# RepoTracker 技术选型与设计依据

本文保留设计阶段的比较与推导。2026-10-16 用户已确认方案；当前技术基线见[技术设计](../../../doc/技术设计.md)，开发进度见[开发里程碑](../../桌面应用开发/doc/里程碑-桌面应用开发.md)。下文“推荐”与候选表属于当时的选型记录。

RepoTracker 是一个通过 Windows 任务栏应用按钮直接展开的 Git 状态观察工具。用户主动添加仓库，快速知道当前分支、是否有改动以及相对上游领先或落后多少，再回到自己的开发工具处理。主面板的快捷操作只有打开目录与解除跟踪。来源识别必须覆盖自建 GitLab，不能依赖 GitHub 账号或云 API。2026-10-16 用户明确希望从任务栏直接点击展开，通知区托盘不再作为主入口。

需求依据是当前 [README](../../../README.md)，其中原有用户修改已保留；本次仅按用户反馈更新入口相关文字。以下结论作为设计建议另行记录。

## 推荐：C# + WPF + .NET 10 + Git CLI

当前范围只针对 Windows，任务栏窗口生命周期、窗口焦点、多屏 DPI、文件选择器和目录打开比 Web 生态或跨平台更重要。因此推荐 WPF，应用核心与视图采用 MVVM 分离，使用 Git for Windows 的 CLI 获取状态，JSON 保存少量配置。无需常驻 Web 服务或数据库。

| 选择 | 适配本项目的依据 | 需要承担的成本 | 本轮判断 |
|---|---|---|---|
| WPF / .NET 10 | ShowInTaskbar 与 WindowState 对接任务栏窗口行为，文件系统与进程控制可集中在 C# | 自定义外观需要 XAML 样式；任务栏附近定位和失焦逻辑需验证；安装方式需权衡运行时依赖 | 推荐 |
| Tauri 2 / Rust / Web UI | 官方支持托盘，提供定位、自启等插件；适合复用 Web UI 或走向跨平台 | Windows 使用 WebView2；同时维护 Rust 与前端；需验证焦点与多 DPI；目前 PATH 未发现 Rust 工具链 | 有明确跨平台或前端复用需求时再考虑 |
| Electron / TypeScript | Chromium 与 Node.js 生态成熟，界面实现方便 | 随包运行 Chromium，进程模型与部署组成对当前小工具偏重 | 本轮不选 |

这些判断来自项目需求与官方能力说明，不是已经完成的性能对比测试。README 中“约 10MB”“内存最低”“150MB+”不可作为本项目实测结论，实际要同时统计应用、子进程和运行时成本。本次调整无需更换 WPF 技术建议，但必须改变窗口生命周期，不能继续沿用 NotifyIcon 为中心的方案。`Shell_NotifyIconGetRect` 只用于通知区图标，不能拿来定位任务栏应用按钮。

## 任务栏入口合同

主窗口使用 `ShowInTaskbar=true`，并接受出现在 Alt+Tab 中的标准窗口行为。收起使用 `WindowState=Minimized`；不要调用 Hide 后假设未固定的应用按钮仍会存在。使用单实例激活及一致的 AppUserModelID，让启动快捷方式与运行窗口归为同一任务栏按钮，避免重复实例和额外图标。

点击任务栏按钮由 Windows 启动、激活或恢复窗口；窗口已在前台时，重复点击通常最小化。恢复时再计算面板位置。点击“收起”同样最小化，保持检查调度运行。默认失焦收起，但不能因打开本应用设置、菜单或文件夹选择器而把整个流程最小化；“保持展开”关闭这一自动收起行为。退出命令真正退出进程，快捷方式是否留在任务栏由用户的固定状态决定。

“固定到任务栏”由用户通过系统菜单完成，或在用户主动触发后请求系统固定；系统版本和策略可能影响 API 可用性。不能静默固定。任务栏右键菜单由 Windows 管理，应用内的设置、自启和退出继续由应用菜单提供；后续可评估 Jump List 常用任务。

原型展示任务栏附近的紧凑面板。精确锚到应用按钮的矩形目前没有经过技术验证；任务栏按钮与通知区图标不是同一定位 API。先做当前显示器工作区边界约束，验证鼠标点击、键盘激活、图标重排、自动隐藏、多任务栏与 DPI。若精确矩形不可稳定取得，降级到当前显示器任务栏边缘或上次位置，并在技术验证后确认细节。禁止把 Explorer 注入、硬编码任务栏内部窗口类名或旧 DeskBand 当作默认依赖。

本机注册表报告 Windows 10 22H2 / build 19045.6466；该事实只用于后续本机验证准备，不代表已经测试了窗口行为。MCP 画板以任务栏应用区为入口示意，Windows 10 与 Windows 11 均需实际验证。

截至本轮检查，本机具备 .NET SDK 10.0.201、WindowsDesktop Runtime 10.0.5、Git 2.51.0.windows.1。选择 .NET 10 LTS；不继续沿用 README 中的 .NET 8 候选版本。发布时再固定 SDK 与依赖补丁版本，不使用浮动版本。

## 应用结构

- `Desktop`：任务栏应用窗口、展开/收起、应用菜单、设置、文件夹选择、目录打开；最小化不停止调度，退出进程才停止检查。
- `Core`：RepoRegistry、SourceResolver、StatusEngine、Scheduler、配置模型；以不可变状态快照通知界面。
- `Infrastructure`：Git CLI 适配器、JSON 配置原子写入、路径规范化、文件系统监听与 Win32 小型适配层。
- 计划中的测试入口：Core 的状态解析与来源匹配单元测试，隔离临时仓库的 Git 合同测试，桌面启动与多 DPI 验证。当前均尚未创建。

先用 `INotifyPropertyChanged` 或小型 MVVM 工具；是否引入 CommunityToolkit.Mvvm 随代码阶段决定。Git CLI 放到接口后，不使用每个仓库一个常驻进程。配置放在用户 LocalAppData 的 RepoTracker 专属目录，带 schemaVersion、原子替换与损坏备份；这属于未来应用配置，不涉及复制工程到 C 盘。

## 手动分组模型

2026-10-16 用户确认任务栏原型方向并提出手动分组。分组是用户定义的列表归类，与仓库托管来源、磁盘父目录和 Git common dir 独立。第一轮采用单层、单归属，不提供嵌套、自动分类或拖动排序；自定义组按创建顺序显示，系统未分组固定在最后。折叠组只改变呈现，不暂停采集。

配置增加 `RepoGroup { id, name, order, collapsed }` 和 `Repo.groupId`。名称只作显示，稳定 ID 用于引用；未分组以 null 表达。名称 trim 后 1–30 个字符，按 Unicode NFC 与不区分大小写比较重复，空白名称拒绝。旧配置缺失 groupId 或引用已不存在的组时回退未分组，不丢弃仓库。组名、归属和折叠状态随配置保存。

新建组允许为空；重命名不改变归属；删除组先确认受影响数量，再将仓库 groupId 清空并移除组记录，原子保存。迁移仓库分组不执行磁盘移动或任何 Git 命令。添加仓库可选目标组，默认未分组；若保存时目标组已不存在，回退未分组并提示。系统未分组不能改名或删除。

界面仍使用 WPF 的集合分组和 MVVM 状态绑定，技术路线无需变更。实施时验证创建及重名、移动后的唯一归属、删除后的仓库数不变、旧配置兼容与重启恢复；这些业务测试尚未实现。大量分组时应按屏幕工作区限制窗口高度，只滚动仓库内容并保留标题和底部入口。

## Git 合同与“只查看”的边界

本地状态的候选调用为 `git --no-optional-locks -C <path> status --porcelain=v2 --branch -z --untracked-files=normal`。必须使用进程参数数组与固定命令，不能拼接 shell。解析 v2 header 与 NUL 分隔记录，区分 initial branch、detached HEAD、上游缺失、冲突、未跟踪文件。`branch.ab` 缺失表示未知或不可比较，不能填成 0。

Git CLI 优先于 libgit2 是为了沿用用户当前 Git 行为及 worktree 支持，减少凭据、配置与版本行为差异；这不是断言 libgit2 不能胜任。开工时仍需测量大仓库运行成本，必要时再评估长期进程或库方案。

`fetch` 不改工作区文件，但会下载对象并更新远程跟踪引用等 Git 元数据，因此它不是严格意义的只读。本轮原型不执行 fetch。产品延续 README 的可关闭远程层方案；实现必须明确默认值与首次使用说明，限定目标 remote、超时、非交互凭据行为和允许更新的引用，不能直接信任任意 fetch refspec 会保持只读。远程数据只是最近一次成功检查的快照，不是持续实时状态。

无上游时显示“无上游”，不替用户设置 upstream；分离 HEAD 显示短提交 ID。仓库外 worktree 的分支不得新增或修改 tracking。身份去重按规范化工作树根目录，不按 Git common dir 合并，否则会吞掉同仓库的不同 worktree。

本地检查初始间隔 15 秒，全局并发上限 2；远程检查间隔 10 分钟并错峰，同一 Git common dir 的写入型远程刷新要串行。事件监听只补充轮询：`.git` 事件不能覆盖未提交工作区文件修改；还要解析 worktree 的 gitdir / commondir，并保留周期兜底、事件合并和恢复后的重新检查。超时取消应回收子进程，不弹凭据窗口或离线错误弹窗。

## 状态数据与呈现

建议在 README 的模型上补充 `worktreeRoot`、`gitDir`、`commonDir`、`upstream`、可空 `ahead/behind`、`lastLocalCheckAt`、可空 `lastSuccessfulFetchAt`、`freshness` 和分层错误。`dirty` 与同步关系是两回事，“干净”不能替代“与远程一致”。无 remote 是本地仓库，不应与未知托管服务混为一谈。

来源规则将 HTTPS、SSH URL 和 scp 风格 URL 归一成 host。精确规则优先于通配规则；通配按域名标签匹配，`*.example.com` 不匹配 `evil-example.com`。匹配结果只影响展示，不改 remote URL。重叠规则需明确优先级，提供匹配预览；不在状态面板散布配置细节。

## 验证目标

性能目标是待测的验收预算，不能当作现状：在固定的 20 个普通测试仓库、面板收起、远程关闭的场景，记录预热后 5 分钟的 CPU、工作集、Git 子进程数与总检查耗时；同时记录仓库规模、机器配置和未跟踪目录情况，再确定数值阈值。避免先许诺未经测量的内存数字。

原型可验证信息层级、文字、状态区别和导航；不能验证真实任务栏激活、面板定位、失焦、多屏缩放、开机启动、Git 性能或凭据行为。后者在实施工作区中建立真正的桌面验收。
