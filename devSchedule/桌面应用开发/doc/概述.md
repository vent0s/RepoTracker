# 桌面应用开发 — 背景与实施边界

用户已确认任务栏点击展开与手动分组原型，并要求用工作区跟踪开发任务。本工作区把设计变成可构建、可测试的 Windows 桌面应用；唯一进度入口是[里程碑](里程碑-桌面应用开发.md)，本文只保存开工背景和依赖。

## 已有与尚无

开工依据包括 README、40 个 Penpot 画板、29 条通过结构检查的关键交互和分组主面板截图。仓库现已建立 solution、csproj、产品窗口与测试源码，原型脚本仍只作为设计资料。部分原型后续弹窗的 PNG 导出曾超时，画板和结构证据保留；实际 WPF 布局以桌面测试生成的截图验收。

本机在前一阶段探测到 .NET SDK 10.0.201、WindowsDesktop Runtime 10.0.5、Git 2.51.0.windows.1、Windows 10 22H2；这里只转录当时结果，不视为当前补丁或 Windows 11 验证。工程建立时复查工具链，发布时核查支持条件。

正式行为以[技术设计](../../../doc/技术设计.md)、[交互设计](../../../doc/交互设计.md)和[README](../../../README.md)为依据；原设计工作区保留比较、画板映射和历史验证，不再维护另一份开发任务清单。

## 首个可用闭环

用户能从任务栏展开面板，添加本机 Git 仓库，手动分组并持久保存，查看本地状态，打开目录或解除跟踪。首版即包含手动分组；来源规则、远程检查及发行打包按依赖后续接入。全程不提供 commit / push / pull 等 Git 客户端操作。

## 工程组织

下列工程入口已经建立；用途列包含后续模块的职责，不代表所有仓库、Git 或配置功能已经实现。

| 位置 | 用途 |
|---|---|
| `RepoTracker.slnx`、`global.json`、构建配置 | 解决方案、SDK 与依赖版本约束 |
| `src/RepoTracker.Desktop` | WPF 入口、视图与 ViewModel、窗口和系统适配组合 |
| `src/RepoTracker.Core` | 状态模型、仓库与分组业务、来源和调度规则、端口接口 |
| `src/RepoTracker.Infrastructure` | Git CLI、配置、路径和文件监听实现 |
| `tests/RepoTracker.Core.Tests` | 业务规则及文本解析的快速测试 |
| `tests/RepoTracker.IntegrationTests` | 隔离文件系统、配置、进程与 Git 行为测试 |
| `tests/RepoTracker.Desktop.Tests` | 可自动化的桌面启动、焦点与关键操作检查 |
| `tests/RepoTracker.Desktop.TestHost` | 在独立进程中加载真实 App 的桌面测试编排，非产品运行依赖 |

以项目现有环境直接实施，不创建 C 盘工程副本，不自行创建分支或 worktree；保留 README、`.agents/` 及其他用户改动。测试临时数据使用项目所在 E 盘，注入独立配置根和进程启动参数，清理前核对绝对路径。验证方式见 [harness](harness.md)。

## 需要实施证据的决策

任务栏图标精确锚定未验证，先以工作区内可靠展开为完成条件；若技术验证证明只能稳定定位到任务栏边缘，就明确记录实际行为，不拖住仓库业务开发。Windows 11、多显示器或特定 DPI 环境缺失时，只标记对应组合未验证。

远程首次启动默认关闭，用户开启才检查；这是将原型演示转为产品的初始默认值。fetch 的目标与引用限制必须在接入前实现。安装形式、签名与可支持系统矩阵在发行阶段根据实测确定，不影响前面的工程和业务任务。

稳定结论维护在仓库 `doc/`；阶段证据和临时执行记录写入本工作区，测试夹具留在将来实际依赖它们的 tests 目录，避免把 devSchedule 变成运行依赖。
