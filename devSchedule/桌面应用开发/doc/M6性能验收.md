- SDK 10.0.401，WindowsDesktop / Runtime 10.0.12；Git 2.56.0.windows.2。`global.json` 仍锁定 10.0.201，本轮从项目外使用绝对路径构建作兼容验证，没有复验锁定 SDK。
- 20 个测试自有 detached HEAD 仓库，每个 201 个已跟踪文件、50 个未跟踪文件，共 5,020 个文件、17,408,780 字节（16.60 MiB）。未跟踪文件位于各仓库的同一子目录，保持产品默认 `--untracked-files=normal`，不代表大量平铺未跟踪路径的成本。没有命名分支或 upstream，不使用真实仓库。
- 本地每次完成后 15 秒重查，并发 2；变更每批写 20 个文件，批间等候 200ms。远程默认关闭，远程阶段设为 1 分钟、全局串行，只向测试自有回环端点尝试 HTTPS，端点立即断开连接。

## 测量方式

复用真实 App、窗口、调度器和 Git CLI，测试宿主只负责场景编排。预热 30 秒后，收起且远程关闭 300 秒、展开 60 秒、持续变更 60 秒、远程失败 90 秒、关闭远程并收起恢复 120 秒。独立进程生成变更，避免把负载写入成本计入应用 CPU。

CPU 和累计后代进程数采用 Windows Job Object，保留已退出的短命 Git 及辅助进程成本；100% 单核口径等于占满一个逻辑核，本机整机口径再除以 12。计量依据见 Microsoft 的[作业记账结构](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_basic_accounting_information)及[子进程继承规则](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)。

每秒采样应用工作集、私有字节、句柄、线程、托管内存及分配量。Git 后代的工作集及同时存活数量只报告采样峰值下界；不能相加当作整机独占物理内存。UI 响应为 Input 优先级 Dispatcher 排队延迟，展开为恢复请求到下一次 Rendering 事件，不等于显示器呈现或人工操作评估。调度耗时通过 Changed 事件观察，跨阶段检查归入完成阶段。宿主、计量和回环服务开销计入应用，无强制 GC。

累计后代进程包括 Git 启动包装和辅助程序，不等于检查次数；本地并发上限 2、远程上限 1 均按逻辑检查计算。

## 复现入口

在满足锁定 SDK 的环境中，先 Release 构建，然后使用 PowerShell 7：

```powershell

pwsh -File tests/run-performance.ps1 -Smoke
pwsh -File tests/run-performance.ps1
pwsh -File tests/run-performance.ps1 -CheckBudgets
```

本轮兼容构建在项目外的 `C:\BuildScratch\repotracker` 执行：

```powershell
dotnet build C:\Projects\repotracker\RepoTracker.slnx --configuration Release --no-restore
```

## 结果与门槛

首轮基线（预热不计入下表）：

| 场景 / 时长 | 平均整机 CPU，含 Git | 应用工作集峰值 MiB | 应用私有字节峰值 MiB | 本地检查数 | 本地检查 P95 ms | UI 排队 P95 ms | 累计 Git 后代进程 |
|---|---|---|---|---|---|---|---|
| 收起 / 300s | 1.32% | 135.17 | 78.90 | 395 | 206.02 | 0.67 | 2,368 |
| 展开 / 60s | 1.18% | 139.27 | 84.85 | 80 | 134.55 | 0.22 | 480 |
| 持续变更 / 60s | 7.93% | 137.75 | 84.22 | 527 | 153.93 | 1.44 | 3,167 |
| 远程失败 / 90s | 1.80% | 148.65 | 92.27 | 122 | 128.08 | 0.13 | 1,170 |
| 关闭远程并收起 / 120s | 1.24% | 149.76 | 91.04 | 157 | 142.00 | 0.22 | 940 |

收起阶段应用自身平均占整机 CPU 0.15%，其余 1.17% 来自 Git 后代；应用数值包含测试宿主。写入器在压力阶段执行 5,440 次追加写入，约 90 次 / 秒。本地检查全部无错误，并发峰值 2；20 个仓库均有成功检查和有效监听。远程失败 40 次，覆盖全部 20 个仓库，并发峰值 1，P95 179.69ms。窗口恢复到 Rendering 事件为 42.37ms，调度退出清理 3.22ms，残留后代进程 0。

后台首 / 尾一分钟均值相比，私有字节增长 5.37 MiB、句柄增加 26.05；压力后的恢复阶段分别为 0.43 MiB、8.57。托管内存和句柄随 GC / 检查阶段波动，这些短时数据没有达到资源增长门槛，但不能证明全天无泄漏。

依据首轮数据建立[回归门槛](../../../tests/performance-budgets.json)，为机器负载波动保留余量，并限制吞吐量与资源增长，避免单看低 CPU 掩盖检查停摆：

- 后台、展开、恢复的平均 CPU 不超过单核口径 30%（本机整机 2.5%）；持续变更不超过 150%（整机 12.5%）；远程失败不超过 40%（整机 3.33%）。
- 应用工作集峰值 ≤ 200 MiB，私有字节峰值 ≤ 128 MiB；后台 / 恢复首尾一分钟私有字节均值增长 ≤ 16 MiB，句柄均值增长 ≤ 64。
- UI 排队 P95 ≤ 50ms、最大值 ≤ 250ms；窗口恢复到 Rendering ≤ 500ms；本地检查 P95 ≤ 500ms，远程失败 P95 ≤ 1,000ms；退出清理 ≤ 2,000ms，残留进程必须为 0。
- 固定数据集、完整预热和各阶段时长、至少 4,000 次变更写入、各阶段最小检查数、Git 后代创建速率和并发边界均由[检查脚本](../../../tests/check-performance.ps1)验证。远程必须覆盖全部 20 个仓库，关闭阶段不能有远程尝试。

门槛针对当前机器与固定工作负载，不代表所有仓库 / 硬件的服务保证。首轮套用门槛和独立完整复跑均通过，构造的短流程标记及超预算 CPU 报告被检查脚本拒绝。
