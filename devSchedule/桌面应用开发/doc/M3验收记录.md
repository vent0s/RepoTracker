## H-05：调度、界面与退出

队列默认间隔 15 秒、并发 2、启动间隔 100ms，事件去抖 400ms / 上限 2 秒。周期是从上次检查结束起算，排队及 Git 执行时间另计。没有每仓库常驻进程；没有仓库时等待信号。

[调度测试](../../../tests/RepoTracker.Core.Tests/StatusSchedulerTests.cs)通过可控时间和暂停任务验证 20 仓库并发限制、不重入、刷新合并、周期轮询、文件事件去抖、删除后的迟到结果、立即重加、暂停取消、恢复错峰、失败保留旧快照、退出等待与监听释放。真实监听测试分别修改工作树文件和 commonDir 配置，确认触发通知；长轮询间隔下仍通过文件事件获得新状态。

[真实窗口流程](../../../tests/RepoTracker.Desktop.TestHost/StatusProbe.cs)验证：

1. 六仓库完成本地检查，显示分离 HEAD、短 SHA、无上游和实际干净 / 有修改。
2. 点击刷新后时间前进，仓库管理仍可用。
3. 在分组折叠和窗口最小化期间修改隔离文件，状态自动变为有修改；窗口和分组不被自动展开。
4. 临时移动测试目录模拟不可达，保留六个条目与上次成功结果；目录还原后检查恢复。
5. 退出回收调度与 Git 任务，再启动独立进程恢复配置；M1 焦点 / 双屏 / 单实例和 M2 管理流程继续通过。

## 失败修复与未覆盖项

- 取消用 `CancelAsync` 传递；测试原先在传递完成前断言全部子令牌取消，已改为等待取消条件再断言。
- 调度审查发现移除后立即重加可能与尚未退出的旧检查重叠；已按 ID 和工作树根排除在运行任务，并测试旧结果无法覆盖新条目。
- 首次全套桌面回归未取得前台焦点。测试原先在原生恢复后固定等待 150ms，已改为 UI Automation 获取焦点并等待前台 HWND 确认，再触发真实失焦；没有降低“必须实际切换焦点”的断言。
- 普通分支 / upstream / 初始未提交的真实集成夹具尚缺，协议层已覆盖。不自行创建 refs 或设置 tracking 来绕过用户约束。
- 暂停 / 恢复通过可控时间与任务验证；未实际让电脑睡眠。监听缓冲区溢出未实机注入，失效时使用定时兜底；远程开关取消留待 M4。
- Windows 11、物理高 DPI / 混合 DPI、任务栏实际鼠标 / 固定 / 自动隐藏和热拔插仍未覆盖。性能和长期资源占用在 M6 测量，本轮不承诺内存或 CPU 数值。
- 未修改全局 Git 配置，未创建项目分支、工程副本、提交或推送。源码、测试与正式证据没有被 `.gitignore` 隐藏。

文档与仓库收尾检查覆盖 84 个源码 / 文档 / JSON 文件、136 个相对链接、14 个锚点，错误 0；`git diff --check` 通过。受限沙箱仍提示全局 ignore 读取权限，当前用户环境复查无告警，未改全局配置。源码、lock 与 M3 证据不被忽略；RepoTracker 桌面进程和带本轮夹具路径的 Git / PowerShell 子进程残留均为 0。
